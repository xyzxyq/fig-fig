# fig-fig

**先确认视觉方案，再把它做成可编辑的学术论文插图。**

`fig-fig` 是一个面向 Codex 的技能，通过用户提供的风格参考、内置图像生成和 Figma 插件/MCP，完成科学问题图、方法框架图与机制示意图的制作、复现和优化。

Reference-guided academic figures: generate a visual draft, obtain user approval, then reproduce and refine it as editable Figma artwork.

## 核心流程

1. **提供材料**：说明要画什么，并提供至少一张具体的风格参考图片。
2. **生成示意稿**：结合科学依据和参考风格，用内置图像生成功能绘制方案。
3. **用户审阅**：不满意则按反馈修订并重新生成；认可当前版本后才进入 Figma。
4. **Figma 复现与精修**：用原生对象重建文字、公式、箭头和结构；复杂科学插画可作为独立高清素材嵌入。
5. **校样与交付**：核对科学关系、可编辑性、排版和论文实际尺寸，交付 Figma 链接及所需导出文件。

**风格参考必须由用户提供或明确指定。** “Nature 风格”“更学术”等文字描述不能替代参考图片，代理自行搜索的图片也不能替代用户的选择。已有有效参考无需重复上传。

## 适用场景

| 任务 | 处理方式 |
|---|---|
| 新画一张科学问题图、方法总图或机制图 | 参考图与内容核对 → 内置生图 → 用户确认 → Figma 复现 |
| 将已选定的示意图做成可编辑版本 | 明确采用该图后直接进入 Figma，避免无意义的重复生图 |
| 优化已有图的箭头、字号、组件和布局 | 保留已有认可内容，针对局部修改并检查相邻影响 |
| 统一同一论文内多张图的风格 | 从用户指定的主参考提取字体、语义颜色、轮廓和组件规则 |
| 在插图中放入真实数据图 | 从真实数据生成曲线、标记和统计量；生图不负责生成或补造数值 |

## 运行条件

- 能加载本地 `SKILL.md` 技能的 Codex 环境。
- 可用的内置图像生成能力；新图流程依赖该能力，仓库本身不提供图像模型。
- 已连接的 Figma 插件/MCP，以及目标文件的相应访问权限。
- 实际制作时使用当前环境的 `imagegen`、`figma-use` 等相关技能和工具说明。

本仓库提供工作流指令与经验文档，不包含 Figma 插件安装包，也不会自动安装或配置上述工具。工具不可用时会说明阻塞，不静默切换到额外付费服务或 API 脚本。

## 安装

将仓库克隆到 Codex 技能目录。以下命令适用于 macOS/Linux shell；设置了 `CODEX_HOME` 时使用该目录，否则使用 `~/.codex`：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
git clone https://github.com/xyzxyq/fig-fig.git "${CODEX_HOME:-$HOME/.codex}/skills/fig-fig"
```

也可下载仓库，将包含 `SKILL.md`、`agents/` 和 `references/` 的整个目录放到技能目录下，命名为 `fig-fig`。Windows 可用同样的目录结构手动安装。

安装后在重新加载技能的 Codex 对话中使用 `$fig-fig`。已安装时不要再次克隆到同名目录；通过 Git 更新前先保存自己的修改。

## 需要提供什么

| 材料 | 要求 |
|---|---|
| 绘图目标 | 图类型、所在章节，以及读者必须看懂的一句话 |
| **风格参考图片** | **必需**；可上传图片、指定可读图片文件/链接，或指定能取得截图的 Figma 图框 |
| 科学内容 | 方法文字、草图或有效证据；不要求所有任务都提供完整代码库 |
| 内容与版面约束 | 必须保留的内容、语言、预计单栏/通栏宽度及禁止修改的部分 |
| 交付位置 | Figma 文件和页面，是否新建版本，以及所需导出格式和保存位置 |

同一张图可由用户明确指定为内容草图兼风格参考。多张参考并存时应指出哪张是主参考。缺少参考图时可以先梳理科学内容，但不会开始生图或新图重设计。

## 使用示例

### 新建论文方法图

在下面的请求中附上实际参考图片和方法材料：

```text
使用 $fig-fig 制作一张论文方法框架图。
图的目标：说明数据输入、表征学习与候选生成之间的关系。
风格参考：我附上的第一张图片；第二张是内容草图。
内容依据：附带的方法段落。
约束：英文，双栏通栏，保留已确认的术语；具体版面宽度见附件。
先用内置生图生成示意稿，等我确认后再用 Figma 复现。
```

### 复现已选定的图

```text
使用 $fig-fig，把我附上的这张已确认示意图在 Figma 中复现。
这张图同时作为风格参考。文字、公式、框架和箭头需要可编辑。
在我提供的 Figma 文件中创建新页面，保留原版本。
```

### 精修已有插图

```text
使用 $fig-fig 优化指定 Figma 图框。
保持现有内容、逻辑与已确认风格，只调整我圈出的箭头、字号和间距。
复杂科学组件如果需要重新生成，仍使用内置图像生成功能。
```

## 制作原则与质量边界

1. **先正确，再好看。** 参考图负责视觉语言，科学材料决定对象、关系和数据；不能为了复现装饰而引入错误机制。
2. **可编辑性有明确范围。** 文字与结构使用原生对象；允许局部科学插画采用位图，含位图时不宣称全矢量。
3. **颜色和形状需要有含义。** 同一角色跨模块保持身份；避免无含义的彩虹条、重复图标或过度抽象。
4. **按最终论文尺寸检查。** 高清 PNG 不保证小字可读；需要检查实际物理尺寸下的字号、细线和素材分辨率。
5. **确认与版本可追溯。** 部分认可不等于整图通过；保留可恢复的版本，不覆盖用户未授权修改的内容。

默认完整交付为 Figma 图框链接、PNG 预览与适用的 SVG/PDF，具体服从用户要求。生成的分子、模拟盒和曲线示意不能当作经过验证的化学结构、模拟轨迹或实验结果。是否满足某一期刊的具体要求，需要依据该刊当前规范单独核查。
